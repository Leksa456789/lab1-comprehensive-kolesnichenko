План code-review модуля `src/discount.py`

1. Цели ревью
- **Точность расчётов:** порядок применения скидок (база, промокоды, уровень лояльности, ограничение 30%) соответствует требованиям.
- **Защита от фрода:** невозможно получить отрицательную или нулевую цену, злоупотребить повторными промокодами или подменить уровень лояльности.
- **Корректность применения скидок:** каждая ветка (SUMMER, VIP, tier 1/2, порог 15000, нижняя граница 70%) работает ожидаемо.
2. Измеримые критерии
| Критерий | Целевое значение |
|---|---|
| Магические числа в коде | 0 (значения вынесены в именованные константы) |
| Валидация входных данных | cart_sum > 0, tier из допустимого набора, promos - список строк |
| Покрытие тестами | > 80% (строк и веток) |
| Замечания flake8 | 0 |
| Критичные замечания ревьюеров | 0 незакрытых перед слиянием |

3. Участники и роли
| Роль | Ответственность |
|---|---|
| Автор (Tech Lead) | Подготовка PR, ответы на замечания, правки |
| Ревьюер 1 (разработчик) | Корректность логики, читаемость, стандарты |
| Ревьюер 2 (QA-инженер) | Тесты, граничные значения, покрытие |
| Ревьюер 3 (безопасность/финансы) | Защита от фрода, корректность денежных расчётов |
| Модератор | Ведёт процесс, следит за сроками (ответ на PR не позже 1 рабочего дня) |

4. Процесс
1. Автор открывает PR в develop, CI (flake8) должен быть зелёным.
2. Ревьюеры проверяют по чек-листу целей и критериев.
3. Автор исправляет замечания, ревьюеры подтверждают (Approve).
4. Слияние после аппрува владельца кода (CODEOWNERS) и выполнения критериев.

5. Эскалация при спорах
1. Автор и ревьюер обсуждают спорный момент в комментариях PR (до 2 итераций).
2. Если согласия нет, модератор выносит вопрос на короткий созвон (15 минут).
3. Если решение не найдено, окончательное решение принимает Tech Lead / владелец продукта и фиксирует его в PR.
4. Вопросы по бизнес-правилам скидок эскалируются владельцу продукта.

6. Чек-лист ревьюера
- [ ] Порядок скидок соответствует UML-диаграмме (docs/uml_diagram.png)
- [ ] Все константы вынесены, магических чисел нет
- [ ] Нет отрицательных и нулевых итоговых цен
- [ ] Неизвестные промокоды и уровни лояльности обрабатываются безопасно
- [ ] Покрытие тестами > 80%, flake8 без замечаний
